# ドラフト修正方針

## 1. 目的
- v1.0.0 を停滞なく公開するため、今回のスコープと記載方針を明確化する。
- 厳密性のみを追うのではなく、実装イメージが伝わる資料としての価値を確保する。

## 2. 本プロファイル群の位置づけ（報告書・各プロファイル冒頭 共通）
- 本プロファイル群は、各コンテンツ事業者に本規定どおりの出力を強制するものではない。
- そもそも xAPI プロファイルの思想自体が、そのような強制力を持たせるものではない。
- 出力方法の方向性を示す「表現のための資産」として位置づけ、「推奨」として扱う。
- 記載項目への準拠を一律に求めない。コンテンツ特性により、ログ未出力や一部項目未充足があっても許容する。
- 上記の位置づけを、報告書および各プロファイル冒頭に共通表現として明記する。
- また、本プロファイル群が xAPI 1.0.3 ベースであることを明記する。
- なお、学習eポータルと連携する際は、「初等中等教育におけるシステム間連携のための相互運用標準モデル Version 5.00」も参照するよう明記する。

## 3. 仕様書の記述方針（前提）
- 仕様書は、特定製品を前提にせず、現実的な範囲の「架空ツール」を想定した記述とする。
- この前提を明記することで、既存システムとの部分的不一致や未確定要素による議論停滞を回避する。

### 4.2 Core の扱い
- Core の位置づけ・収載内容は、今回十分に合意形成できていない。
- 学年・教科・学習指導要領コード・単元メタデータを Core にどう集約するかは継続議論とする。
- メタデータ以外（例: verbs などの日本独自仕様）は今回はスコープ外とする。
- v1.0.0 は、現時点で Core が未整備でも公開可能と判断する。
- これまで Core に置いていた extensions は、当面は各ドメインプロファイルへ戻す。
- 上記について、報告書に明記する。

### 4.3 コンテンツメタデータ
- 学年・教科・学習指導要領コード等の「コード体系の選定」は SWG のスコープ外であることを報告書に明記する。
- 現状の前提は次のとおりとする。
	- 学習指導要領コードは、コード体系として整備されている。
	- 学年コードは、文部科学省「教育データ標準5.0」の「主体情報」において、APPLIC教育情報アプリケーションユニット標準仕様（校務基本情報データ連携 小中学校版V2.2）に基づき整備されている。
	- 教科コードは、文部科学省「教育データ標準5.0」の「内容情報」において、APPLIC教育情報アプリケーションユニット標準仕様（校務基本情報データ連携 小中学校版V2.2）に基づき整備されているが、平成20～21年改訂時点の体系であり、同改訂で追加された教科コードには対応していない。また、学習指導要領コードの3桁目・4桁目で教科・科目等を表現できるものの、教科・科目コードとして正式に位置づけられたものではない。
- コード体系自体はスコープ外だが、メタデータ記録枠を規定した際の事業者影響の見通しと検討時間が不足しており、本バージョンで最終決定には至っていない。
- 一方で、メタデータ記載方法は日本の標準規格としての位置づけを踏まえ、将来的に Core プロファイルへ整理していく方向性は共有されている。
- あわせて、`question-order`（問題の出題順序）、`content-order`、`content-index`（コンテンツ順序）はプロファイル規定外とし、実装依存として扱う。

### 4.4 verb の共通化
- 起動・終了等の verb 共通化は、各タスクフォースで検討した。
- ただし、コンテンツ特性により開始・終了を明確に定義できる場合と定義しづらい場合があり、現時点では統一に至っていない。
- 例えば、終了条件を明確に定義できるコンテンツもあれば、終了の境界が曖昧なコンテンツもある。
- 本バージョンでは、定義可能な範囲でステートメントテンプレートに記載する。
- 将来的に統一可能な項目は、継続して共通化を検討する。

## ebookの扱う対象について
ebookでは、デジタル教科書・教材などではなく、「電子書籍型デジタル教材」という表現に統一する。IRIやタイトルなどの表現はebookのままである。特に、デジタル教科書といった表現があれば必ず削除する。

## 5. サンプル提示の方針

### 5.1 ねらい
- 「最小限の規定」と「実装イメージの伝達」を両立する。
- xAPI-Spec から逸脱しない範囲で、利用者が理解しやすい具体例を提示する。

### 5.2 基本方針
- サンプルは「あくまで一例」であることを明示する。
- JSON-LD への厳密な収載可否とは分けて、人間可読な仕様書には必要な説明・概念を残す。

### 5.3 提供方法（案）
- JSON-LD を読み込んで確認できるシミュレーターを作成し、納品物に含める。
- 各事業者が `include` 項目等を入力し、生成結果のイメージを把握できるようにする。
