xAPI Japan Profiles

教育アプリが生み出すスタディ・ログを、事業者や領域をまたいで読み解ける共通表現へ。

Profileを見る Statement例を見る
Why

学習ログに、共通言語が必要です。

GIGAスクール構想によって、LMS、デジタルドリル、CBT、電子書籍ビューアなど、多様なアプリが大量の学習活動データを生成するようになりました。各サービスが独自形式でログを出力すると、自治体や学校がデータを統合するたびに変換コストが生じます。

xAPI Japan Profiles は、xAPI 1.0.3 を前提に、国内の初等中等教育で流通するスタディ・ログの書き方を領域別に揃えるためのドラフトです。

xAPI

「誰が・何をした・何に対して」をStatementとして記録します。

actor 誰が

学習者、教員、システムなど、学習活動の主体を表します。

verb 何をした

回答した、閲覧した、開始したなどの行為をIRIで識別します。

object 何に対して

問題、課題、ページ、投稿など、行為の対象を表します。

プロファイルは、xAPI の柔軟な枠組みに対して、Concepts と StatementTemplate / Rules を与えることで、同じ学習行動を同じ読み方で扱えるようにする語彙集と記述ルール集です。

Profiles

4つのドメイン別Profileを定義しています。

01 LMS Profile 学習課題の作成、配布、開始、完了、フィードバック、閲覧、異常終了、初期化、免除などを扱います。主なExtensionは modules、due-date、range です。 読む 02 Assessment Profile CBTやデジタルドリルの開始、問題への回答、学習コンテンツやページの参照、終了を扱います。得点率、素点、最大点、回答値、所要時間を揃えます。 読む 03 ebook Profile プラットフォーム起動/終了、紙面表示/非表示、ページ移動、しおり・ブックマーク、書き込み、削除などの操作ログを扱います。 読む 04 Group Learning Support Tool Profile 他者の共有成果物・投稿物へのコメントや返信、いいね等のスタンプ送信を扱います。投稿や共同編集は今後の拡張対象です。 読む

Assessment Profileを適用したStatement例。

Implementation

実装は、TemplateとRulesから始めます。

  1. 対象ドメインを選ぶ LMS、Assessment、ebook、Group Learning Support Tool のうち、自システムの学習行動に合うProfileを確認します。
  2. ユースケースを対応づける 記録したい学習行動を StatementTemplate の一覧に対応づけます。該当しない行動は、Extensionや別プロファイルとの共存を検討します。
  3. Statementを生成・検証する Rulesに沿って、必須要素、IRI、値の型、ISO 8601形式などを確認します。
  4. LRSへ送信する xAPI 1.0.3 準拠の LRS や学習 eポータル等に送信し、蓄積・分析に利用します。
Value

ログを出す側にも、受け取る側にも効きます。

教材アプリ・LMS開発者

  • 他の準拠ベンダーのデータと集計・比較しやすい形式になる
  • 「どんなデータを出すべきか」の設計ガイドとして使える
  • 学習 eポータル等との連携実装を進めやすい

LRS運用者・自治体・プラットフォーム

  • 複数ベンダーのログの前処理・変換コストを削減できる
  • StatementTemplate の Rules を参照した検証がしやすい
  • 学習データ分析の再現性・信頼性を高められる
FAQ

よくある質問

完全準拠は必須ですか。
いいえ。本プロファイルは推奨として位置づけられており、共通化できる部分から段階的に対応することが想定されています。
複数ドメインにまたがる場合は。
LMSがドリル機能を内包する場合など、Statementごとに対応するProfileのTemplateを参照して組み合わせます。
未定義の学習行動はどう扱いますか。
Extensionを使って独自データを付与できます。IRIの衝突を避けるため、自組織ドメインのIRIを使用してください。
