# xAPI Japan Profiles 紹介記事
## 〜 教育アプリ事業者・システム関係者の方へ 〜

> **対象読者**: 学習管理システム（LMS）・デジタルドリル・電子書籍型教材・グループ学習支援ツールの開発・提供に携わるエンジニア、プロダクトマネージャー、データアーキテクト

---

## 1. はじめに ── 学習ログの「共通言語」が必要な理由

GIGAスクール構想によって全国の学校に1人1台端末が普及し、学習活動の記録（スタディ・ログ）を多様なアプリが大量に生成するようになりました。国語のドリルアプリ、英語のCBT、学校配布のLMS、電子書籍ビューア……それぞれのアプリが独自の形式でログを出力している現状では、自治体や学校が複数サービスのデータを統合しようとすると膨大な変換コストが生じます。

この課題を解決するのが **xAPI（Experience API）** と **xAPI プロファイル** です。

---

## 2. xAPI とは

**xAPI（Experience API）** は、米国 ADL（Advanced Distributed Learning）が策定した、学習活動データを記述するための国際標準仕様です（最新安定版 xAPI 1.0.3）。大学・企業・軍など世界の多くの学習基盤で採用されており、国内でも京都大学の科研費事業や内閣府SIP事業でいち早く採用されました。

### xAPI Statement の基本構造

xAPI では、学習活動を **「誰が・何をした・何に対して」** という3要素の JSON で表現します。

```json
{
  "actor": {
    "objectType": "Agent",
    "account": {
      "homePage": "https://lms.example.jp",
      "name": "user-12345"
    }
  },
  "verb": {
    "id": "http://adlnet.gov/expapi/verbs/answered",
    "display": { "ja-JP": "回答した" }
  },
  "object": {
    "objectType": "Activity",
    "id": "https://drill.example.jp/questions/q-001",
    "definition": {
      "type": "http://adlnet.gov/expapi/activities/cmi.interaction",
      "name": { "ja-JP": "第1問：分数の加法" }
    }
  },
  "result": {
    "success": true,
    "score": { "raw": 1, "min": 0, "max": 1 }
  },
  "timestamp": "2026-04-15T09:23:00+09:00"
}
```

この JSON ひとつが「Statement（ステートメント）」と呼ばれ、LRS（Learning Record Store）に蓄積されます。

### xAPI の利点

| 観点 | 内容 |
|------|------|
| **標準化** | 動詞（Verb）・活動タイプ（ActivityType）を IRI（URI）で一意に識別 |
| **柔軟性** | 教室内・教室外・ゲームなど多様な学習活動を同一フォーマットで記録 |
| **相互運用性** | 異なるベンダーのアプリ間でデータを統合・分析しやすい |
| **拡張性** | Extensions により独自データを付与可能 |

## 3. xAPI プロファイルとは

xAPI の仕様は「どういう JSON を書けばよいか」という枠組みを提供しますが、**「何をどう書くべきか」の詳細はベンダー任せ** です。たとえば「問題に回答した」という行為を記録する際、あるベンダーは `answered` という動詞を使い、別のベンダーは `responded` を使う可能性があります。これでは集計・比較ができません。

**xAPI プロファイル**（xAPI Profile Specification 準拠）は、この問題を解決するための「語彙集 + 記述ルール集」です。

```
xAPI Profile = Concepts（語彙定義） + StatementTemplate（記述ルール）
```

- **Concepts** ── このプロファイルで使用する Verb・ActivityType・Extension を IRI で定義
- **StatementTemplate** ── 特定のユースケースにおいてどの要素を必須とするかのルール
- **Rules** ── 各要素の値の制約（必須・推奨・禁止 など）

世界では IMS Global や ADL が公開している多数のプロファイルが存在しますが、**日本の初等中等教育に特化したプロファイルは従来存在しませんでした**。

---

## 4. xAPI Japan Profiles プロジェクト

**ICT CONNECT 21** の xAPI サブワーキンググループ（xAPI SWG）が中心となり、国内の教育 DX 事業者が参画して策定したのが **xAPI Japan Profiles**（ドラフト）です。

### プロジェクトの目標

> 日本国内で流通するスタディ・ログの記述内容を整理し、**事業者間で合意された統一的な記述形式**を策定することで、教育データの円滑な流通と効果的な学習分析の実現を目指す。

### 基本方針

- **強制ではなく推奨**: プロファイルはデータ表現の共通資産であり、各事業者に一律の実装を強制するものではない
- **xAPI 1.0.3 ベース**: 既存 LRS との円滑なデータ連携を確保
- **学習 eポータル連携考慮**: 「初等中等教育におけるシステム間連携のための相互運用標準モデル Version 5.00」も参照
- **ドメインごとに分割管理**: LMS・Assessment・ebook・グループ学習の各領域に対応

---

## 5. 定義されているプロファイル

本リポジトリでは以下の4つのドメイン別プロファイルが定義されています（v1.0.0）。

### 5.1 LMS Profile

**対象システム**: 学習管理システム（LMS）・学習 eポータル

**プロファイル IRI**: `https://w3id.org/xapi-japan-profiles/lms/v1.0.0`

学習課題の配布・提出・評価などのプロセスに関する学習ログを記録するためのプロファイルです。

**主なユースケース（StatementTemplate）**:

| ユースケース | 行為の例 |
|---|---|
| 課題の配布 | 教員がクラスに学習課題を配布した |
| 課題の取り組み開始 | 学習者が課題に取り組み始めた |
| 課題の提出 | 学習者が完成した課題を提出した |
| 課題の評価 | 教員・システムが提出物に得点や評価を付与した |

**独自 Concepts（主な Extension）**:

| Extension | 用途 |
|---|---|
| `modules` | 学習課題を構成する子課題群（教科・単元情報など） |
| `due-date` | 配布期間（開始・終了 ISO 8601 形式） |
| `range` | 配布対象（学校・学年・クラス・生徒） |

---

### 5.2 Assessment Profile（CBT / デジタルドリル）

**対象システム**: CBT（Computer Based Testing）・デジタルドリル

**プロファイル IRI**: `https://w3id.org/xapi-japan-profiles/assessment/v1.0.0`

設問への回答・採点・アセスメント全体の開始/終了といった基本ワークフローを記録するプロファイルです。

**主なユースケース（StatementTemplate）**:

| ユースケース | 行為の例 |
|---|---|
| アセスメント開始 | 学習者がドリル/テストを開始した |
| 問題への回答 | 学習者が設問に対して解答を送信した |
| コンテンツの参照 | 学習者がヒントや解説を参照した |
| アセスメント終了 | 学習者がドリル/テストを終了した |

**記録できるデータの例**:
- 各設問の得点率・素点・最大点・回答値・所要時間
- アセスメント全体のスコア・完了状況
- 一回のアセスメント取り組みを識別するグループID

**v1.0.0 の特徴**: Assessment Profile v1.0.0 では独自 Concepts は定義せず、ADL 等の既存 Verb と StatementTemplate の Rules によって、得点・回答・所要時間などの記録項目を揃えます。

**v1.0.0 の範囲外（今後の課題)**:
- IRT（項目反応理論）に基づく能力推定値（θ値）の記録
- アダプティブラーニングの動的出題制御ログ

---

### 5.3 ebook Profile（電子書籍型デジタル教材）

**対象システム**: 電子書籍ビューア・デジタル教科書プラットフォーム

**プロファイル IRI**: `https://w3id.org/xapi-japan-profiles/ebook/v1.0.0`

電子書籍型教材上のプラットフォーム起動/終了、紙面表示、ページ移動、しおり・ブックマーク、書き込み、削除などの操作ログを記録するプロファイルです。

**主なユースケース（StatementTemplate）**:

| ユースケース | 行為の例 |
|---|---|
| プラットフォームの起動 | 学習者が電子書籍型デジタル教材プラットフォームを起動した |
| プラットフォームの終了 | 学習者が電子書籍型デジタル教材プラットフォームの利用を終了した |
| 紙面の表示/非表示 | 学習者が書籍全体または章節の紙面を表示/非表示にした |
| ページ移動 | 学習者が特定ページへ移動した |
| しおり・ブックマーク作成 | 学習者がページ等にしおり・ブックマークを作成した |
| 書き込み作成 | 学習者がページ上に線分・手書き線・文字情報を書き込んだ |
| 削除 | 学習者が書き込みやしおり等の注釈を削除した |

**特徴**: 閲覧行動が非線形（任意のページに移動可能）な特性を踏まえ、Pattern（順序制約）は定義しない。検索、辞書連携、音声読み上げ、外部リンク遷移、学習完了、読書行動（`read`）は v1.0.0 では今後の検討課題として整理されています。

---

### 5.4 Group Learning Support Tool Profile（グループ学習支援ツール）

**対象システム**: 協働学習支援ツール・グループ議論プラットフォーム

**プロファイル IRI**: `https://w3id.org/xapi-japan-profiles/group-lst/v1.0.0`

グループ学習支援ツール内で、他者の共有成果物・投稿物に対してコメントやスタンプを送る操作を記録するプロファイルです。

**主なユースケース（StatementTemplate）**:

| ユースケース | 行為の例 |
|---|---|
| 共有成果物へのコメント | 学習者が他者の共有成果物・投稿物にコメントや返信を書いた |
| スタンプ送信 | 学習者が他者の共有成果物・投稿物に「いいね」等のスタンプを送った |

**特徴**: v1.0.0 では他者への反応に関する操作ログを主な対象とします。自分や自分たちの考えを文章・図表・成果物等で表現する活動や、共同編集の関係性を一貫して記録するテンプレートは今後の拡張対象です。

## 6. xAPI Statement の例（Assessment Profile）

実際にアセスメントで設問に回答した際の Statement サンプルです。Assessment Profile v1.0.0 の「問題への回答」テンプレートで定義されている項目に絞っています。

```json
{
  "actor": {
    "objectType": "Agent",
    "account": {
      "homePage": "https://drill.example.jp",
      "name": "student-00987"
    }
  },
  "verb": {
    "id": "http://adlnet.gov/expapi/verbs/answered",
    "display": { "ja-JP": "回答した" }
  },
  "object": {
    "objectType": "Activity",
    "id": "https://drill.example.jp/assessments/math-2026/questions/q-005",
    "definition": {
      "name": { "ja-JP": "第5問：一次方程式" },
      "description": { "ja-JP": "一次方程式を解く問題" }
    }
  },
  "result": {
    "response": "b",
    "score": { "scaled": 1, "raw": 1, "max": 1 },
    "duration": "PT45S"
  },
  "context": {
    "contextActivities": {
      "grouping": [
        {
          "id": "https://drill.example.jp/assessments/math-2026/attempts/attempt-0001"
        }
      ]
    }
  },
  "timestamp": "2026-04-15T10:12:45+09:00"
}
```

このように、**誰が・何の問題に・どう答えたか・得点はいくつか・何秒かけたか** を、Assessment Profile の Rules に沿って構造化して記録できます。選択肢一覧、正解パターン、インタラクションタイプなどは xAPI として表現可能な場合がありますが、Assessment Profile v1.0.0 の「問題への回答」テンプレートでは必須・推奨項目として定義していないため、この例では扱っていません。

## 7. 事業者にとってのメリット

### ログを出力する側（教材アプリ・LMS 開発者）

- 本プロファイルに沿って実装することで、他の準拠ベンダーのデータと集計・比較しやすい形式になる
- 「どんなデータを出すべきか」の設計ガイドとして活用でき、仕様策定のコスト削減につながる
- 学習 eポータル等との連携実装が円滑になる

### ログを受け取る側（LRS 運用者・自治体・EdTech プラットフォーム）

- 複数ベンダーのログの前処理・変換コストを削減できる
- プロファイルを参照した静的バリデーションが可能になる（StatementTemplate の Rules 活用）
- 学習データ分析の再現性・信頼性が向上する

### 全体として

- 「日本の教育データ流通の共通言語」として機能し、教育 DX の加速に貢献する
- 各ベンダーが持つ独自拡張を排除するのではなく、共通部分を揃えた上で独自性を上乗せできる設計

## 8. プロファイルの活用方法

### Step 1: 対象ドメインのプロファイルを読む

本リポジトリの各プロファイルドキュメントを参照してください。

| ドメイン | ドキュメントパス |
|---|---|
| LMS | `lms/v1.0.0/lms_profile.md` |
| CBT / デジタルドリル | `assessment/v1.0.0/assessment_profile.md` |
| 電子書籍型デジタル教材 | `ebook/v1.0.0/ebook_profile.md` |
| グループ学習支援ツール | `group-lst/v1.0.0/group-lst_profile.md` |

### Step 2: 自システムのユースケースを整理する

プロファイルに定義された StatementTemplate の一覧と、自システムで記録したい学習行動を対応づけます。

- プロファイルに合致するユースケース → プロファイルの Template に従い実装
- プロファイルに存在しないユースケース → Extensions を活用、または個別プロファイルを設計（本プロファイルと共存可能）

### Step 3: Statement を実装・検証する

各 StatementTemplate の **Rules（検証規則）** に沿って Statement を生成します。

- 必須要素が揃っているか確認
- IRI の形式が正しいか確認
- 値の型・フォーマット（ISO 8601 の日付形式など）が正しいか確認

### Step 4: LRS に送信・蓄積する

生成した Statement を、xAPI 1.0.3 準拠の LRS（学習 eポータル等）に送信します。

## 9. よくある質問

**Q: プロファイルへの完全準拠が必須ですか？**  
A: いいえ。本プロファイルは「推奨」として位置づけられており、一部項目を出力しない、または本プロファイルとは異なる別のプロファイルを別途定義することも許容されます。まずは共通化できる部分から段階的に対応することをお勧めします。

**Q: 複数ドメインにまたがるシステムはどのプロファイルを使えばよいですか？**  
A: LMS がドリル機能を内包する場合など、複数プロファイルを組み合わせて利用することが想定されています。各 Statement ごとに対応するプロファイルの Template を参照してください。

**Q: プロファイルに定義されていない独自の学習行動はどう記録しますか？**  
A: Extension を使って Statement に独自データを付与することができます。ただし Extension の IRI は衝突を避けるため、自組織ドメインの IRI を使用してください。

**Q: xAPI 以外のログ形式（Caliper Analytics 等）との関係は？**  
A: 本プロファイルは xAPI ベースですが、Caliper Analytics との相互変換や共存については今後の検討課題として位置づけられています。
